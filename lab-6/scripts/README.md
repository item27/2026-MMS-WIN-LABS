# Лабораторная 6 — Windows Server 2012/2016

Скрипты предназначены для Windows PowerShell 5.1, не для Linux. Запускайте в тестовой VM от администратора; проверьте политику и права. Сначала `01-create-log.ps1`, затем `02-process-monitor.ps1`, `03-register-task.ps1`, `04-event-report.ps1`. Планировщик использует SYSTEM, поэтому папка скриптов должна быть ему доступна. Проверка: `Start-ScheduledTask Lab6-ProcessMonitoring`, `Get-ScheduledTaskInfo Lab6-ProcessMonitoring`, CSV в C:\Lab6\ProcessData и события ProcessMonitoringLog; дождитесь также двух запусков по расписанию. Повторение ограничено 3650 днями. CPU — средняя доля от мощности всех логических процессоров за приблизительно 2 секунды; путь/владелец могут отсутствовать из-за прав, процесс мог завершиться или PID переиспользоваться.

## Часть 3: представление
В Event Viewer → Custom Views → Create Custom View выберите Security, событие 4625; вкладка XML → Edit query manually. Замените `Administrator` на фактическое локализованное имя или имя учётной записи администратора:
```xml
<QueryList><Query Id="0" Path="Security"><Select Path="Security">*[System[(EventID=4625)]] and *[EventData[Data[@Name='TargetUserName']='Administrator']]</Select></Query></QueryList>
```
Для появления событий необходимо настроить аудит неудачного входа. Отчёт скрипта использует событие 6005 как приближение включения и событие 19 как успешную установку обновления; неполные или очищенные журналы дают неполные данные. Ошибки и предупреждения считаются отдельно для System и Application, не для всех журналов.

## Часть 4: ручная настройка и результаты
В perfmon.msc создайте User Defined Data Collector Set с Performance Counter, интервал 5 с: `Processor(_Total)\% Processor Time`, `Memory\Available MBytes`, `PhysicalDisk(_Total)\% Disk Time`, `Network Interface(*)\Bytes Total/sec` (локализованные имена могут отличаться). Добавьте Event Trace Data Collector с провайдером ядра Windows (доступные провайдеры зависят от версии); для kernel flags может понадобиться отдельная kernel-сессия. Запустите на одинаковый период при сценарии A, остановите и сохраните BLG/ETL; повторите при B, не перезаписывая первый результат. Откройте оба отчёта Performance Monitor, экспортируйте BLG через `relog` в CSV, постройте графики и сравните CPU, свободную память, диск и сеть. ETL преобразуется `tracerpt`. Реальные измерения и выводы нужно получить в VM.

## Часть 5: только выделенный диск VM
Создайте и отформатируйте отдельный диск около 200 MiB, укажите его букву явно: `05-fill-test-disk.ps1 -Drive E:`; `06-clean-test-disk.ps1 -Drive E:`. Заполнение ограничено 180 файлами до 1 MiB. Очистка удаляет только файлы вида `lab6-<32 hex>.bin` в каталоге Lab6GeneratedFiles с маркером на томе 150–250 MiB; остальные файлы не трогает. Не используйте том с чужими данными: размер и маркер не доказывают назначение диска. Системный том запрещён; проверяются также точки повторной обработки каталога и маркера. Размер, маркер и имя не являются доказательством принадлежности файлов: заранее ограничьте ACL каталога и диска администраторами и SYSTEM и исключите одновременную подмену путей (проверки не атомарны).

Для автоматического реагирования создайте в Task Scheduler задачу от SYSTEM с действием `powershell.exe -NoProfile -File "<полный путь>\06-clean-test-disk.ps1" -Drive E:` и разрешением запуска по запросу. В perfmon создайте отдельный Performance Counter Alert: LogicalDisk(E:)\% Free Space ниже 20, включите запись в Application event log и укажите имя задачи в Alert Task. Проверьте разрешения, запуск и журнал; при несовпадении версии используйте GUI/документацию данной ОС. Сравните с PhysicalDisk и счётчиками Free Megabytes: PhysicalDisk относится к физическому диску, а LogicalDisk — к разделу; % Free Space и абсолютный объём имеют разные единицы. Фактическую причину неожиданного поведения устанавливайте экспериментально, не предполагайте её заранее. Проверка задания: `schtasks.exe /Query /TN "Lab6-Cleanup" /V /FO LIST` (имя должно совпадать с созданным).

Проверки выполнения на Windows и артефакты отчёта (скриншоты, графики, сравнение) должны быть получены пользователем; скрипты не создают VM, диск или Perfmon-настройки автоматически.
