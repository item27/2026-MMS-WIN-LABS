# Памятка для защиты лабораторной работы №2

Открывайте этот файл для повторения команд, устройства скрипта и ответов на вопросы. Связный текст выступления на двоих вынесен в [отдельный рассказ](lab-2-defense-speech.md)

## Что, зачем и почему делали

Порядок работы связан с зависимостями: сеть -> домен и его службы -> клиент в домене -> пользователи и права -> политики -> автоматизация и восстановление

- Серверу задали постоянный адрес `10.0.0.1`, чтобы клиент обращался к службам по известному адресу. DNS сервера и клиента указывает на сервер домена. DHCP выдаёт клиенту адрес из пула `10.0.0.100-10.0.0.110`, DNS и шлюз. Выданный шлюз сам по себе не настраивает маршрутизацию и не обеспечивает интернет
- В AD создали домен `GMAKMA.local`. После присоединения клиент использует доменные учётные записи, а администратор управляет ими на сервере
- В OU разместили пользователей и компьютеры, чтобы привязывать к ним нужные GPO. Группы использовали для выдачи файловых прав: при появлении нового сотрудника достаточно включить его в соответствующую группу
- В папках `Sellers` и `Managers` разрешили работу со вложенными файлами, сохранив запрет удаления самой папки отдела и изменения её разрешений. Проверяли доступ из сессий обычных пользователей
- `BlackHole` использовали как приёмную папку: файл можно передать перетаскиванием, но список содержимого просматривать нельзя. В `Common` пользователи могут создавать и изменять файлы, а удалять только свои. Это не личное хранилище с запретом изменения чужих файлов
- Домашняя папка на X: хранит пользовательские файлы. Перемещаемый профиль сохраняет настройки и данные среды Windows на сервере. У пользователей части 3 профиль расположен в `_profile` внутри личного ресурса, у CSV-пользователей - в отдельном `Profiles$`
- GPO позволяют задавать настройки для OU централизованно. У продавцов проверили запрет Панели управления и редактора реестра, скрытие C: и блокировку после 60 секунд бездействия. У менеджеров проверили разрешённые Paint, Калькулятор и Блокнот
- Автоматизация нужна, чтобы по одной таблице подготовить учётные записи и файловые ресурсы. Корзину проверили, чтобы уметь вернуть ошибочно удалённый объект с его прежней идентичностью

## Как запускать скрипт по шагам

1. На `ad-srv` войти администратором домена и открыть Windows PowerShell 5.1 через Run as administrator. Нужны модули `ActiveDirectory` и `SmbShare`, действующий домен и права на создание объектов и настройку файловых ресурсов
2. Проверить наличие `C:\Lab2\Provision-Lab2.ps1` и закрытого рабочего CSV `C:\Lab2Private\lab2-users.csv`. Каталог `C:\Lab2` для HTML должен уже существовать. Публичный пример из репозитория содержит заменители паролей и не является готовым рабочим CSV
3. Выполнить команду ниже. Это рабочий запуск с изменением AD и файловых ресурсов. У скрипта нет реализованного режима `-WhatIf`

```powershell
C:\Lab2\Provision-Lab2.ps1 `
    -CsvPath C:\Lab2Private\lab2-users.csv `
    -ReportPath C:\Lab2\provision-demo.html
```

4. Проверить `Status = Completed` и открыть `C:\Lab2\provision-demo.html`. Там перечислены созданные за этот запуск OU, группы, пользователи, каталоги, файлы и ресурсы SMB. Для повторного показа выбирать отдельное имя HTML, чтобы сохранить прежние результаты
5. Проверить пользователя в ADUC: OU, группы, атрибуты HomeDrive, HomeDirectory и ProfilePath. На клиенте войти этим пользователем, проверить X:, запись файла, выход и повторный вход для проверки профиля

Обязателен только `-CsvPath`. Параметр `-ReportPath` выбирает выходной HTML. По умолчанию `-HomeRoot` равен `C:\UsersHome`, `-ProfileRoot` равен `C:\Profiles`, `-ProfileShareName` равен `Profiles$`. Если их переопределить, пути в CSV должны соответствовать выбранным хранилищам

В CSV столбцы разделены запятыми, несколько групп внутри поля `Groups` разделены `;`. Для `uCsvSeller1` домашний путь в AD - `\\ad-srv\uCsvSeller1$`, локальная папка - `C:\UsersHome\uCsvSeller1`, путь профиля - `\\ad-srv\Profiles$\uCsvSeller1`. Суффикс `$` скрывает ресурс из обычного списка, а доступ защищают разрешения SMB и NTFS

Рабочий CSV содержит пароли в открытом виде, поэтому его хранят в закрытом каталоге и не показывают на защите. Преобразование пароля в `SecureString` перед созданием пользователя не шифрует исходный CSV

## По каким местам скрипта вести объяснение

| Место | Что объяснить преподавателю |
|---|---|
| `param(...)` | Принимает входной путь и настройки хранилищ и HTML |
| `Read-Lab2Csv` | Читает CSV, проверяет 11 заголовков и число ячеек каждой строки. Лишняя ячейка считается ошибкой |
| `Assert-Lab2Sam`, `ConvertTo-Lab2OuDn`, `Assert-Lab2Root`, `Assert-Lab2NoReparse` | Проверяют логины, принадлежность OU текущему домену и допустимость путей |
| `Phase 1` | Проверяет весь CSV и существующие цели до записи: повторы логинов, конфликты имён и ресурсов, существующего пользователя в другой OU |
| `Phase 2`, `New-ADOrganizationalUnit`, `New-ADGroup` | Создаёт недостающие OU от родительских к дочерним и глобальные группы безопасности |
| `New-ADUser`, `Set-ADUser`, `Add-ADGroupMember` | Создаёт учётную запись, задаёт атрибуты, X: и профиль, добавляет недостающее членство. Начальный пароль используется только при создании |
| `Add-Lab2Directory`, `Set-Lab2DirectoryAcl`, `Set-Lab2Share` | Создаёт каталоги и скрытые ресурсы, настраивает права и перечитывает результат. Личную папку профиля создаёт Windows при первом входе |
| `Write-Lab2Inventory`, `catch`, `finally` | Пишет HTML, при ошибке пытается сохранить частичный результат, очищает поля паролей в загруженных строках |

Функции в начале файла описывают операции. Основное выполнение начинается с `Phase 1`, а изменения начинаются только в `Phase 2`. Скрипт части 5 не устанавливает роли сервера и не настраивает GPO

## Вопросы, на которых легко запутаться

- Почему сначала OU и группы? Пользователю нужны существующая OU для размещения и существующие группы для добавления в них
- Чем OU отличается от группы? OU определяет размещение объектов и область привязки GPO, группа объединяет учётные записи для назначения прав. Членство в группе само по себе не переносит пользователя в OU этой группы
- Почему UNC, а не `C:\UsersHome\имя` в свойствах пользователя? Клиенту нужен сетевой путь к серверу. Локальный C: клиента относится к его собственному диску
- Почему на втором запуске нули? Счётчики показывают только новые объекты за этот запуск. Атрибуты и права при этом могут записываться заново, недостающие членства добавляются, прежние членства сохраняются, пароли существующих пользователей не сбрасываются. Новый HTML считается отдельным новым файлом
- Что будет при ошибке? Ошибочный формат CSV отклоняется до записи. Ошибка во время создания может оставить часть объектов, общего автоматического отката нет. Нужно посмотреть HTML и фактическое состояние перед повтором
- Почему надо проверять SMB и NTFS? При сетевом доступе операция должна быть разрешена на обоих уровнях. Скрытое имя ресурса не заменяет проверку прав
- Скрытый C: недоступен? Политика скрывает диск в интерфейсе Проводника. Разрешения на его файлы определяются отдельно
- Менеджер может запустить только три программы при любых условиях? Проверенная политика ограничивает запуск через Explorer. Полной изоляции произвольного кода она не обеспечивает
- Как доказали восстановление? До удаления сохранили manifest пяти пользователей. Скрипт восстановления выбирает удалённые объекты по исходным GUID и проверяет их прежнюю OU, затем восстанавливает через `Restore-ADObject`. После этого сверяет SID и логин, отдельно проверены группы и пользовательский вход
- Можно просто создать пользователя заново с тем же логином? Это создаст другой объект с новым GUID и SID. В работе восстановлены исходные объекты из корзины, включённой до удаления

Подробные ответы на обязательные теоретические вопросы преподавателя находятся в разделе 7 [guide](lab-2-guide.md), команды удаления и восстановления с проверками - в его разделе 6
