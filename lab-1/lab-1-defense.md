# Теория к защите лабораторной №1 — инструменты управления Windows Server

> Конспект для устной защиты: что было сделано, какие термины нужно знать и как отвечать на типовые вопросы. Пароли и другие секреты в документ не включены.

## 1. Цель и итог работы

**Цель:** собрать MMC-консоль, настроить локальные учётные записи и IPv4, затем повторить эти действия сценариями CMD и PowerShell.

В работе подготовлены:

- настраиваемая MMC-консоль `C:\Console\lab-1.msc`;
- ограниченная копия `C:\Console\LAB-1-USER.msc`;
- локальный пользователь `UPart1GMAKMA`;
- локальная группа `GPart1GMAKMA`, в которую включён пользователь;
- выделенный интерфейс `Lab-Isolated` с IPv4 `192.168.1.10/24`, шлюзом `192.168.1.1` и DNS `8.8.8.8`;
- четыре сценария CMD и PowerShell;
- папка Taskpad `Tools` с Network Connections и задачами запуска сценариев.

## 2. MMC: что это и зачем нужна

**MMC (Microsoft Management Console)** — оболочка `mmc.exe`, в которую можно собрать несколько административных оснасток и сохранить их как файл `.msc`. Сама MMC не управляет ресурсами: это делают подключённые оснастки (**snap-ins**).

В консоль добавлены четыре требуемые оснастки:

| Оснастка | Назначение |
|---|---|
| **Computer Management** | Сводная оснастка: системные инструменты, хранилища, службы и другие административные компоненты. |
| **Services** | Просмотр свойств и состояния служб, изменение типа запуска, запуск, остановка и перезапуск при наличии прав. |
| **Event Viewer** | Просмотр журналов Windows: Application, System, Security и журналов приложений/служб. Используется для диагностики ошибок. |
| **Shared Folders** | Управление общими ресурсами, открытыми файлами и подключёнными сеансами SMB. |

### Как создаётся консоль

1. Запустить `mmc.exe` от имени администратора.
2. Выбрать **File → Add/Remove Snap-in**.
3. Добавить требуемые оснастки для **Local computer**.
4. Сохранить через **File → Save As** в `C:\Console\lab-1.msc`.

Почему запуск от администратора важен: MMC можно открыть обычным пользователем, но многие операции оснасток потребуют повышенных прав и будут недоступны или завершатся `Access denied`.

## 3. Taskpad и папка Tools

**Taskpad view** — представление MMC с ярлыками задач. Оно даёт быстрый доступ к часто используемым действиям.

В папке `Tools` созданы пять задач:

1. **Network Connections** — команда `control.exe` с параметром `ncpa.cpl`; открывает список сетевых адаптеров.
2. **SCRIPT21.CMD**.
3. **SCRIPT22.CMD**.
4. **SCRIPT31.PS1**.
5. **SCRIPT32.PS1**.

Для CMD используется `cmd.exe`, для PowerShell — `powershell.exe`. Taskpad только запускает команду. Она работает с правами пользователя, который открыл MMC; UAC он не обходит и административные права сам не выдаёт.

## 4. Локальные пользователи и группы

### Основные понятия

- **Локальная учётная запись** хранится в SAM (Security Accounts Manager) конкретного компьютера и действует только на нём.
- **Локальная группа** собирает пользователей, которым нужны одинаковые права. Это удобнее, чем назначать права каждому отдельно.
- **Членство в группе** добавляет SID группы в access token пользователя. При проверке доступа Windows сравнивает этот токен с ACL объекта.
- **Принцип наименьших привилегий** означает, что обычному пользователю дают только нужные права, а администрирование оставляют отдельной учётной записи.

Для части 1 были созданы:

```text
Пользователь: UPart1GMAKMA
Группа:      GPart1GMAKMA
Членство:    UPart1GMAKMA ∈ GPart1GMAKMA
```

Проверка членства в CMD:

```cmd
net localgroup GPart1GMAKMA
```

Полезные команды:

```cmd
net user                         :: список локальных пользователей
net user UPart1GMAKMA            :: свойства пользователя
net localgroup                   :: список локальных групп
net localgroup GPart1GMAKMA      :: члены группы
```

### Почему новый пользователь имеет несколько групп

У учётной записи есть собственная локальная группа с тем же именем. Также могут быть стандартные группы, например `Users`; это зависит от локальной политики. В работе отдельно создана `GPart1GMAKMA`, и её состав проверяется через `net localgroup`.

## 5. Службы Windows и проверка обычного пользователя

**Windows service** — фоновый компонент под управлением Service Control Manager (SCM). У службы есть состояние (`Running`, `Stopped`, …), тип запуска (`Automatic`, `Manual`, `Disabled`) и ACL, который определяет, кто может ею управлять.

В ограниченной консоли `LAB-1-USER.msc` под `UPart1GMAKMA` проверена служба **DHCP Client**. Команды **Start**, **Stop**, **Pause** и **Resume** недоступны. Это ожидаемо: обычный пользователь видит оснастку, но не получает право управления системной службой.

Для администратора эти операции доступны при достаточных правах. Видимость объекта в MMC не означает право управления им: Windows проверяет маркер доступа пользователя и разрешения службы.

### Ограниченная консоль

Копия `C:\Console\LAB-1-USER.msc` сохранена в режиме:

```text
User mode – limited access, single window
Do not save changes to this console
```

Такой режим не даёт обычному пользователю менять структуру MMC или сохранять её настройки. Он не заменяет Windows ACL и не повышает права: MMC ограничивает интерфейс, а права на службы и системные объекты проверяет ОС.

## 6. IPv4: параметры и смысл

На выделенном изолированном интерфейсе `Lab-Isolated` установлено:

| Параметр | Значение | Назначение |
|---|---|---|
| IPv4-адрес | `192.168.1.10` | Адрес хоста в сети. |
| Prefix length | `/24` | Первые 24 бита — адрес сети; соответствует маске `255.255.255.0`. |
| Маска | `255.255.255.0` | Отделяет часть сети от части узла. |
| Шлюз | `192.168.1.1` | Маршрутизатор для пакетов в другие сети. |
| DNS | `8.8.8.8` | Сервер преобразования имён в IP-адреса. |

### Как вычисляется сеть

При маске `/24` сеть — `192.168.1.0/24`, широковещательный адрес — `192.168.1.255`, а диапазон адресов узлов обычно `192.168.1.1`–`192.168.1.254`. Адрес `192.168.1.10` находится в этой сети; `192.168.1.1` может быть шлюзом.

### DHCP и статическая настройка

- **DHCP / Auto**: IP-адрес, маска, шлюз и часто DNS получаются автоматически от DHCP-сервера.
- **Manual / static**: параметры задаются явно и не меняются без административного действия.

В лабораторной VM `Lab-Isolated` подключён к отдельному bridge и не смешивается с основным `Ethernet`. Поэтому сценарии меняют только `Lab-Isolated` и не затрагивают основной адаптер.

### Несколько IPv4-адресов на одном интерфейсе

Один интерфейс может иметь несколько IP-адресов. В графическом интерфейсе: свойства IPv4 -> **Advanced** -> **IP addresses** -> **Add**. В PowerShell нужны несколько вызовов:

```powershell
New-NetIPAddress -InterfaceIndex <ifIndex> -IPAddress 192.168.1.10 -PrefixLength 24
New-NetIPAddress -InterfaceIndex <ifIndex> -IPAddress 192.168.1.11 -PrefixLength 24
```

В `netsh` используется `add address`, а не `set address`, потому что `set` заменяет основную конфигурацию.

## 7. CMD-сценарии

### `script21.cmd`: пользователь и группа

Сценарий запрашивает строку ровно из четырёх символов без пробелов. Из неё формируются имена вида:

```text
UPart2STR
GPart2STR
```

Затем `net user` и `net localgroup` создают пользователя и группу, добавляют пользователя в группу и активируют его.

Ключевые идеи CMD:

- `set /p` читает ввод;
- `if` реализует ветвление;
- `net user` управляет локальными пользователями;
- `net localgroup` управляет группами и их составом;
- `%VAR%` — подстановка переменной окружения.

### `script22.cmd`: IPv4 через `netsh`

Сценарий предлагает `Auto` или `Manual`.

```cmd
netsh interface ipv4 set address name="Lab-Isolated" source=dhcp
netsh interface ipv4 set dnsservers name="Lab-Isolated" source=dhcp
```

В `Manual` назначаются статические IP, маска, шлюз и DNS:

```cmd
netsh interface ipv4 set address name="Lab-Isolated" static 192.168.1.10 255.255.255.0 192.168.1.1
netsh interface ipv4 set dnsservers name="Lab-Isolated" static 8.8.8.8 primary validate=no
```

`validate=no` отключает проверку доступности DNS во время применения. В изолированной учебной сети адрес DNS может быть недоступен, поэтому эта проверка здесь не нужна.

## 8. PowerShell-сценарии

### `script31.ps1`: пользователь и группа

PowerShell-версия использует cmdlet-ы:

```powershell
New-LocalUser
New-LocalGroup
Add-LocalGroupMember
Enable-LocalUser
```

Проверка ввода выполняется регулярным выражением:

```powershell
^[^\s]{4}$
```

Оно означает: ровно четыре символа, и ни один не является пробельным. В исходнике используется `-NoPassword`, поэтому пароль там не хранится. В рабочей среде пароль надо задавать безопасным интерактивным способом, а не записывать в код.

### `script32.ps1`: IPv4

Сценарий строго выбирает интерфейс:

```powershell
$adapter = Get-NetAdapter -Name 'Lab-Isolated' -ErrorAction Stop
```

Так надёжнее, чем выбирать «первый активный адаптер»: на сервере их может быть несколько.

В режиме `Manual` выполняется очистка старого маршрута по умолчанию и прежних IPv4-адресов именно этого интерфейса, после чего добавляется новый адрес:

```powershell
Get-NetRoute -InterfaceIndex $adapter.ifIndex -DestinationPrefix '0.0.0.0/0' |
  Remove-NetRoute -Confirm:$false
Get-NetIPAddress -InterfaceIndex $adapter.ifIndex -AddressFamily IPv4 |
  Remove-NetIPAddress -Confirm:$false
New-NetIPAddress -InterfaceIndex $adapter.ifIndex -IPAddress 192.168.1.10 `
  -PrefixLength 24 -DefaultGateway 192.168.1.1
Set-DnsClientServerAddress -InterfaceIndex $adapter.ifIndex -ServerAddresses 8.8.8.8
```

Очистка не даёт повторному запуску создать дубликат IP-адреса или маршрута `0.0.0.0/0`.

## 9. CMD и PowerShell: сравнение

| Критерий | CMD | PowerShell |
|---|---|---|
| Модель работы | Текстовые команды и строки. | Объекты .NET и cmdlet-ы. |
| Типичные команды здесь | `net`, `netsh`. | `New-LocalUser`, `Get-NetAdapter`, `New-NetIPAddress`. |
| Обработка данных | Разбор строк и переменные `%VAR%`. | Свойства объектов, конвейер `|`, переменные `$var`. |
| Обработка ошибок | Обычно код возврата и текст вывода. | `-ErrorAction`, исключения, структурированная обработка. |
| Поддерживаемость | Удобен для простых старых команд. | Лучше для сложной автоматизации и фильтрации объектов. |

CMD удобен для простых системных команд. PowerShell обычно лучше подходит для администрирования, потому что работает с объектами, а не с неструктурированным текстом.

## 10. Удалённое управление через оснастку

Многие оснастки MMC подключаются к другому компьютеру через **Connect to another computer**. Для этого нужны:

1. сетевой маршрут и разрешение имени/IP;
2. права администратора либо делегированные права на удалённой системе;
3. доступные службы управления (например, RPC/WMI в зависимости от оснастки);
4. разрешающие правила Windows Firewall;
5. корректные учётные данные и, в доменной среде, настройки аутентификации/Kerberos.

Если подключение не работает, сначала проверяют DNS и маршрут (`ping`, `Test-NetConnection`), затем Firewall, RPC/WMI и права учётной записи. В рабочей среде не нужно отключать Firewall целиком: следует разрешать только нужные правила.

## 12. Вопросы на защите: короткие ответы

**Почему не нужно выполнять всю работу под Administrator?**  Потому что задача демонстрирует разделение прав. Администратор настраивает систему, а обычный пользователь проверяет, что ему не доступны привилегированные операции.

**Почему задача Tools не даёт пользователю права администратора?**  Она только запускает программу или сценарий в текущем контексте безопасности. Право определяется токеном пользователя и ACL целевого объекта.

**Чем отличается интерфейс с IP `192.168.1.10/24` от интерфейса с маской?**  `/24` — краткая CIDR-запись длины маски; ей соответствует `255.255.255.0`.

**Зачем нужен default gateway?**  Он используется для доставки пакетов в сети, которые не являются напрямую подключёнными.

**Зачем нужен DNS, если IP уже задан?**  Адрес позволяет связаться с конкретным узлом; DNS нужен, чтобы по именам находить IP-адреса сервисов и хостов.

**Почему PowerShell сценарий удаляет старые route и IP?**  Чтобы повторный запуск был идемпотентнее: новая конфигурация не конфликтует с оставшейся прежней.

**Можно ли изменить структуру ограниченной MMC обычным пользователем?**  Нет: включён `User mode – limited access, single window`, а сохранение изменений отключено.

**Почему DHCP Client выбран для проверки вместо DNS Client?**  Учетная запись без административных прав не может управлять системными службами; фактически для DHCP Client команды управления были недоступны, что подтверждает корректное ограничение прав.

## 13. Что показать преподавателю

1. Открыть `C:\Console\lab-1.msc` и показать четыре оснастки.
2. Открыть `Tools` и показать пять задач.
3. Показать `net localgroup GPart1GMAKMA`.
4. Показать IPv4-параметры `Lab-Isolated` через `ipconfig /all` или PowerShell.
5. Открыть все четыре файла сценариев и кратко пояснить ветви `Auto`/`Manual` и проверку ввода.
6. Войти как обычный пользователь, открыть `LAB-1-USER.msc` и показать ограничение управления службой.
7. При вопросах открыть `lab-1-report.md`: там есть пошаговые доказательные скриншоты.
