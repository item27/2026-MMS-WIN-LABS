# Пошаговый показ лабораторной №1

Этот файл нужен для повторного прохождения готовой лабораторной перед защитой. Он не заменяет отчёт: отчёт доказывает, что сделано, а здесь описано, что открыть, куда нажать и что сказать преподавателю.

Работать нужно только с VM 107. VM 104 и VM 105 для этого показа не используются.

## 1. Что должно быть готово перед показом

На VM 107 должны быть:

- Windows Server 2025 с Desktop Experience;
- учётная запись `Administrator`;
- обычная учётная запись `UPart1GMAKMA`;
- группа `GPart1GMAKMA`;
- изолированный адаптер `Lab-Isolated`;
- основная консоль `C:\Console\lab-1.msc`;
- ограниченная консоль `C:\Console\LAB-1-USER.msc`;
- каталог `C:\Console\Scripts` с четырьмя сценариями.

Для основного показа войди в Windows как `Administrator`. Пароли в команде и в отчёте не показывай.

## 2. Рекомендуемый порядок показа

Не пытайся открыть всё сразу. Удобный порядок такой:

1. показать состав MMC;
2. показать Tools и быстрые задачи;
3. показать пользователя, группу и членство;
4. показать IP-настройки изолированного адаптера;
5. показать исходники и запуск четырёх сценариев;
6. показать ограниченную MMC под обычным пользователем;
7. ответить на вопросы о правах, сети и различии CMD с PowerShell.

Такой порядок совпадает с логикой задания: сначала инструменты управления, затем учётные записи, сеть, автоматизация и разграничение прав.

## 3. Показ основной MMC-консоли

### Что открыть

1. Нажми `Win + R`.
2. Введи:

```text
C:\Console\lab-1.msc
```

3. Нажми `Enter`.

Если Windows спросит подтверждение UAC, согласись только при входе под Administrator.

### Что показать

В дереве консоли должны быть четыре оснастки:

1. `Computer Management`;
2. `Event Viewer`;
3. `Shared Folders`;
4. `Services`.

Открой каждую по одному разу. Не меняй настройки, если преподаватель не просит.

### Что сказать

> MMC - это оболочка `mmc.exe`. Она сохраняет набор административных оснасток в файле `.msc`. Сама консоль не управляет системой напрямую: работу выполняют подключённые snap-in.

Кратко объясни назначение оснасток:

| Оснастка | Что показать | Как объяснить |
|---|---|---|
| Computer Management | дерево System Tools, Storage, Services and Applications | Сводная административная оснастка для локального компьютера. |
| Event Viewer | Windows Logs -> System или Application | Здесь ищут системные события и ошибки программ. |
| Shared Folders | Shares, Sessions, Open Files | Здесь видны SMB-ресурсы, подключения и открытые файлы. |
| Services | список служб, например DHCP Client | Здесь видны состояние службы, тип запуска и команды управления. |

Если спросят, почему в списке есть и `Computer Management`, и отдельный `Services`, ответь: отдельная оснастка была добавлена по условию задания, хотя внутри Computer Management тоже есть раздел служб.

## 4. Показ папки Tools

### Что открыть

В основной MMC выбери папку `Tools`.

Там должны быть пять задач:

```text
Network Connections
SCRIPT21.CMD
SCRIPT22.CMD
SCRIPT31.PS1
SCRIPT32.PS1
```

### Что проверить

1. Дважды нажми `Network Connections`.
2. Должно открыться окно Network Connections со списком адаптеров.
3. Закрой окно Network Connections.

### Что сказать

> Tools сделан как Taskpad view в MMC. Это набор ярлыков для часто используемых действий. Он запускает команду от имени текущего пользователя и не выдаёт административные права сам по себе.

Для Network Connections используется:

```text
Command:    control.exe
Parameters: ncpa.cpl
```

Если спросят, почему не использовать прямой путь к панели управления, ответь: `control.exe ncpa.cpl` является стандартным способом открыть классическое окно сетевых подключений.

## 5. Показ пользователя, группы и членства

### Через графический интерфейс

1. В MMC открой `Computer Management`.
2. Перейди в:

```text
System Tools -> Local Users and Groups -> Users
```

3. Найди `UPart1GMAKMA`.
4. Перейди в:

```text
System Tools -> Local Users and Groups -> Groups
```

5. Открой `GPart1GMAKMA` двойным нажатием.
6. В списке Members должен быть `UPart1GMAKMA`.

### Через команду

Открой Command Prompt от имени Administrator и выполни:

```cmd
net localgroup GPart1GMAKMA
```

В выводе должен быть пользователь `UPart1GMAKMA`.

Для дополнительной проверки:

```cmd
net user UPart1GMAKMA
```

### Что сказать

> Локальная учётная запись хранится в SAM на конкретной VM. Группа нужна, чтобы выдавать одинаковые разрешения нескольким пользователям. При входе Windows добавляет SID групп пользователя в его access token и затем сравнивает этот токен с ACL объекта.

Если спросят, почему не назначать права каждому пользователю отдельно, ответь: группой проще управлять. Достаточно изменить состав группы, а не править права на каждом объекте.

## 6. Показ изолированной IPv4-настройки

### Через GUI

1. В Tools снова открой `Network Connections`.
2. Найди адаптер `Lab-Isolated`.
3. Нажми по нему правой кнопкой -> `Properties`.
4. Выбери `Internet Protocol Version 4 (TCP/IPv4)`.
5. Нажми `Properties`.

Должны быть видны:

```text
IP address:        192.168.1.10
Subnet mask:       255.255.255.0
Default gateway:   192.168.1.1
Preferred DNS:     8.8.8.8
```

Не нажимай OK с изменёнными полями, если не собираешься менять настройку.

### Через PowerShell

Открой PowerShell от имени Administrator и выполни:

```powershell
Get-NetAdapter -Name 'Lab-Isolated'
Get-NetIPAddress -InterfaceAlias 'Lab-Isolated' -AddressFamily IPv4
Get-NetRoute -InterfaceAlias 'Lab-Isolated' -AddressFamily IPv4
Get-DnsClientServerAddress -InterfaceAlias 'Lab-Isolated' -AddressFamily IPv4
```

### Что сказать

> Настройка сделана на отдельном интерфейсе Lab-Isolated. Он подключён к изолированному bridge Proxmox, поэтому учебный адрес 192.168.1.10 не конфликтует с реальной сетью. Основной Ethernet не менялся.

Если спросят про `/24`, ответь: это длина префикса. `/24` соответствует маске `255.255.255.0`; сеть имеет адрес `192.168.1.0`, широковещательный адрес `192.168.1.255`.

Если спросят, почему задан DNS `8.8.8.8`, хотя сеть изолирована, ответь: это параметр из задания. В изолированной сети сервер может быть недоступен, но конфигурация адаптера задана корректно.

## 7. Показ CMD-сценариев

Исходные файлы находятся здесь:

```text
C:\Console\Scripts
```

Чтобы сначала показать текст, открой Command Prompt от имени Administrator:

```cmd
notepad C:\Console\Scripts\script21.cmd
notepad C:\Console\Scripts\script22.cmd
```

Закрывай Notepad после объяснения каждого файла.

### script21.cmd

Запусти:

```cmd
C:\Console\Scripts\script21.cmd
```

Введи четыре новых символа без пробелов, которых ещё нет среди созданных объектов. Например:

```text
D21A
```

Сценарий создаст:

```text
UPart2D21A
GPart2D21A
```

Затем можно подтвердить:

```cmd
net localgroup GPart2D21A
```

Что сказать:

> Сценарий проверяет, что введено ровно четыре непробельных символа. Потом `net user` создаёт пользователя, `net localgroup` создаёт группу и добавляет пользователя в эту группу.

### script22.cmd

Запусти:

```cmd
C:\Console\Scripts\script22.cmd
```

Для защиты выбирай:

```text
Manual
```

После вывода о применении параметров проверь:

```cmd
ipconfig /all
```

Ищи раздел адаптера `Lab-Isolated`.

Что сказать:

> В ветке Auto сценарий включает DHCP для адреса и DNS. В ветке Manual `netsh` задаёт статический адрес, маску, шлюз и DNS. Параметр `validate=no` нужен потому, что изолированная учебная сеть не обязана иметь доступ к DNS-серверу в момент настройки.

Не запускай Auto прямо перед показом без необходимости: в изолированной сети может не быть DHCP-сервера, и адаптер потеряет статический адрес до повторного запуска Manual.

## 8. Показ PowerShell-сценариев

Открой Windows PowerShell от имени Administrator. Если политика выполнения мешает запуску, используй только для текущего процесса:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Это не меняет постоянную политику системы.

### script31.ps1

Сначала покажи текст:

```powershell
notepad C:\Console\Scripts\script31.ps1
```

Запусти:

```powershell
& 'C:\Console\Scripts\script31.ps1'
```

Введи новые четыре непробельных символа, например:

```text
P31B
```

После запуска можно проверить:

```powershell
Get-LocalGroupMember -Group 'GPart3P31B'
```

Что сказать:

> PowerShell использует cmdlet-ы New-LocalUser, New-LocalGroup и Add-LocalGroupMember. Ввод проверяется регулярным выражением `^[^\s]{4}$`: это ровно четыре символа без пробелов. Пароль не хранится в сценарии.

### script32.ps1

Сначала покажи текст:

```powershell
notepad C:\Console\Scripts\script32.ps1
```

Запусти:

```powershell
& 'C:\Console\Scripts\script32.ps1'
```

Выбери:

```text
Manual
```

После выполнения проверь:

```powershell
Get-NetIPAddress -InterfaceAlias 'Lab-Isolated' -AddressFamily IPv4
Get-DnsClientServerAddress -InterfaceAlias 'Lab-Isolated' -AddressFamily IPv4
```

Что сказать:

> Сценарий обращается к адаптеру по имени Lab-Isolated, а не выбирает первый активный адаптер. Поэтому он не затрагивает основной Ethernet. Перед установкой статических параметров он удаляет старый маршрут по умолчанию и прежние IPv4-адреса только выбранного интерфейса. Это делает повторный запуск предсказуемым.

## 9. Показ ограниченной MMC обычному пользователю

### Переход в учётную запись

1. Закрой административные программы.
2. Выполни `Start -> Sign out`.
3. На экране входа выбери `Other user`.
4. Введи:

```text
.\UPart1GMAKMA
```

5. Введи пароль этой учётной записи.

### Что открыть

1. Нажми `Win + R`.
2. Введи:

```text
C:\Console\LAB-1-USER.msc
```

3. Нажми `Enter`.
4. Открой `Services`.
5. Найди `DHCP Client`.
6. Нажми по службе правой кнопкой.

Команды управления, такие как Start, Stop, Pause и Resume, должны быть недоступны.

### Что сказать

> Эта копия сохранена в User mode - limited access, single window. Обычный пользователь не может менять структуру консоли и сохранять изменения. Кроме того, у него нет прав ACL на управление системной службой DHCP Client. Ограничение MMC и ограничение прав Windows - это два разных механизма.

Если преподаватель попросит показать, что Administrator может управлять службой, не останавливай DHCP Client без необходимости. Достаточно объяснить, что команды доступны администратору при соответствующих разрешениях, а обычному пользователю они выключены.

## 10. Частые вопросы и короткие ответы

### Почему MMC не даёт права администратора?

MMC - это только интерфейс. Каждая оснастка запускает действия с токеном текущего пользователя. Если права нет, Windows откажет в операции.

### Чем CMD отличается от PowerShell?

CMD передаёт и разбирает текстовые команды. PowerShell работает с объектами и cmdlet-ами. Для простых старых задач удобен CMD, а для сетевых объектов и фильтрации обычно удобнее PowerShell.

### Почему Tools не повышает права?

Taskpad запускает команду в контексте пользователя, который открыл консоль. Это ярлык, а не механизм повышения прав.

### Зачем нужен шлюз, если IP и маска уже есть?

Маска определяет локальную сеть. Шлюз нужен для отправки трафика в другие сети.

### Как добавить второй IP на тот же адаптер?

В GUI: IPv4 Properties -> Advanced -> IP addresses -> Add. В PowerShell: повторно вызвать `New-NetIPAddress` для того же InterfaceIndex. В netsh: использовать `add address`, а не `set address`.

### Почему в `script32.ps1` сначала удаляются старые IP и маршрут?

Иначе повторный запуск может оставить старый default gateway или создать конфликтующий адрес. Очистка относится только к `Lab-Isolated`.

### Что делать, если после запуска сетевого сценария исчез IP?

Проверь, что выбран режим Manual, затем повторно запусти `script22.cmd` или `script32.ps1` и введи `Manual`. Не применяй эти сценарии к основному Ethernet.
