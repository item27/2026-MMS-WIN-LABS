## Что показать преподавателю

Создать обычного пользователя на новом DC через графический мастер и впервые войти этой учёткой с клиента. В показе 18.11.2026 проверен lab3gui1118. Для сдачи выберите другое имя, например lab3demo01, и сначала убедитесь, что его нет в Users

| Окно VNC | Машина | Что делаем |
|---|---|---|
| Win Labs 3, VM109 | AD-SRV-2, 10.0.0.2 | Создаём доменного пользователя |
| Win Labs 2, VM105 | AD-CLIENT | Выполняем первый вход |

### Термины перед показом

DC обслуживает домен. ADUC - оснастка Active Directory Users and Computers. LOGONSERVER показывает сервер входа в текущем сеансе. Kerberos-билет TGT используется для получения билетов к службам домена

## 1. Создать пользователя на Win Labs 3

Войти на AD-SRV-2 под администратором домена и открыть Server Manager

1. В правом верхнем углу открыть Tools -> Active Directory Users and Computers. Меню Manage для этого шага не используется
2. В дереве слева раскрыть GMAKMA.local и выбрать Users. Здесь создаём обычную тестовую учётку, без групп продавцов и менеджеров
3. Нажать правой кнопкой по Users -> New -> User
4. В First name ввести выбранное имя. Full name заполнится автоматически. В нашем показе оба поля содержат lab3gui1118
5. В User logon name ввести то же имя. Справа оставить суффикс @GMAKMA.local. В поле pre-Windows 2000 должно получиться GMAKMA\lab3gui1118
6. Нажать Next. В Password и Confirm password ввести согласованный лабораторный пароль, не показывая его на экране
7. Для нашего показа оставить все четыре флажка снятыми: User must change password at next logon, User cannot change password, Password never expires, Account is disabled
8. Нажать Next, проверить имя и нажать Finish. Убедиться, что пользователь появился в Users

## 2. Впервые войти на Win Labs 2

1. Открыть VNC клиента AD-CLIENT
2. Передать Ctrl+Alt+Del кнопкой noVNC и выбрать Switch user, если уже открыт другой сеанс
3. На экране входа выбрать Other user
4. Ввести GMAKMA\lab3gui1118 и пароль. При надписи Sign in to: GMAKMA достаточно имени lab3gui1118
5. Нажать стрелку входа и дождаться рабочего стола. При первом входе Windows может несколько минут готовить профиль

## 3. Подтвердить результат

Открыть Win+R -> powershell -> Enter. Вводить команды по одной, после каждой нажимать Enter. Повышение прав не требуется

Первая команда показывает, под кем выполнен вход:

```powershell
whoami
```

Ожидаем gmakma\lab3gui1118: домен и имя новой учётки

Вторая команда читает переменную с сервером входа текущего сеанса:

```powershell
$env:LOGONSERVER
```

Ожидаем \\AD-SRV-2, то есть новый контроллер. Основное доказательство отсутствия кэша - первый успешный вход только что созданной учёткой

Для дополнительного подтверждения обращения к домену выполнить:

```powershell
klist
```

Это список Kerberos-билетов сеанса. Прокрутить к первым билетам и показать Client: lab3gui1118, Server: krbtgt/GMAKMA.LOCAL и Kdc Called: AD-SRV-2.GMAKMA.local

Основной сценарий - создание и первый вход. whoami и LOGONSERVER поясняют результат, klist дополнительно подтверждает Kerberos. hostname, полный SID и путь профиля для показа необязательны

### Что сказать на защите

«Мы создали новую доменную учётку через графический мастер и впервые вошли ею с клиента. Кэша её предыдущих входов на клиенте ещё не было. Сервер входа и Kerberos указывают на AD-SRV-2»

Для каждого повторения первого входа нужна новая учётка. Подставляйте её имя вместо lab3gui1118 при входе и чтении результатов. Пароль нужно знать заранее
