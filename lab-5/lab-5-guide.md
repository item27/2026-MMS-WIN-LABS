## Часть 1. Подготовительная.

Устанавливаем Windows Server 2022 Standard Evaluation с Desktop Experience в UTM. Используем две отдельные машины, каждой выделяем 3072 МиБ RAM, два ядра CPU и системный диск 64 ГиБ. Для образа x64 на Mac M5 выбран режим эмуляции. Для двух ядер включаем Force Multicore. Если появляются сбои, проверяем их связь с многоядерной эмуляцией

| Машина Windows | Роль | IPv4 | DNS |
|---|---|---|---|
| `ad-srv` | Контроллер домена `GMAKMA.local`, сервер хранения | `10.0.0.1/8` | `10.0.0.1` |
| `ad-srv-2` | Член домена, клиент iSCSI | `10.0.0.2/8` | `10.0.0.1` |

Устанавливаем Windows на каждом сервере независимо. Если используем клон установленной системы, до клонирования выполняем Sysprep с Generalize и завершением работы, затем проходим первоначальную настройку каждого экземпляра. Простую копию установленной Windows с прежним SID для второго сервера не используем

### Имена и сеть

Имена в таблице задаём внутри Windows. Название машины в библиотеке UTM может отличаться: первая ВМ называется `lab5-ad-srv`. На первом сервере открываем Windows PowerShell от имени администратора и переименовываем систему:

```powershell
Rename-Computer -NewName ad-srv -Restart
```

Имя второго сервера задаём при присоединении к домену. Создаём одну именованную Host Network в UTM и выбираем её у обеих выключенных машин. Временные адаптеры Shared Network отключаем. DHCP для этой работы не разворачиваем

На каждом сервере сначала смотрим имя учебного адаптера:

```powershell
Get-NetAdapter
```

В следующих командах `Ethernet` заменяем фактическим именем из вывода, если оно отличается. На `ad-srv` задаём адрес и DNS:

```bat
netsh interface ipv4 set address name=Ethernet static 10.0.0.1 255.0.0.0 none
netsh interface ipv4 set dnsservers name=Ethernet static 10.0.0.1 primary validate=no
```

На втором сервере задаём другой адрес и тот же DNS. Шлюз в изолированной сети не указываем:

```bat
netsh interface ipv4 set address name=Ethernet static 10.0.0.2 255.0.0.0 none
netsh interface ipv4 set dnsservers name=Ethernet static 10.0.0.1 primary validate=no
```

### Создание домена

На `ad-srv` устанавливаем роль AD DS:

```powershell
Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
```

В той же повышенной PowerShell создаём новый лес и устанавливаем DNS:

```powershell
Install-ADDSForest -DomainName GMAKMA.local -DomainNetbiosName GMAKMA -InstallDns
```

Пользователь вводит новый пароль DSRM и его повтор, затем подтверждает продолжение ответом `Y`. Пароль в файлы не записываем. После завершения установки Windows автоматически перезагружается

На первом сервере этот шаг уже выполнен. Запрос `Win32_ComputerSystem` подтвердил домен `GMAKMA.local` и `DomainRole=5`, служба `NTDS` запущена. В cmd проверяем службу и обнаружение контроллера:

```bat
sc query NTDS
nltest /dsgetdc:GMAKMA.local /force
```

На `ad-srv` обе проверки прошли успешно. Это подтверждает работу первого контроллера

На втором сервере открываем повышенную PowerShell. В запросе учётных данных вводим действующий пароль администратора домена, затем одновременно задаём имя `ad-srv-2` и присоединяем машину:

```powershell
$credential = Get-Credential GMAKMA\Administrator
Add-Computer -DomainName GMAKMA.local -NewName ad-srv-2 -Credential $credential -PassThru
```

После результата `HasSucceeded=True` перезагружаем Windows:

```powershell
shutdown.exe /r /t 5
```

Этот шаг выполнен: после перезагрузки проверены имя `AD-SRV-2`, домен `GMAKMA.local`, роль сервера `DomainRole=3` и два логических процессора. Адрес равен `10.0.0.2/8`, DNS равен `10.0.0.1`, профиль сети стал `DomainAuthenticated`, защищённый канал вернул `True`

## Часть 2. Управление разделами

### Подключение и карта дисков

Для учебных дисков используем интерфейс VirtIO. Сначала проверяем, что драйвер `viostor` из официальных гостевых инструментов добавлен в хранилище драйверов Windows. На одном пустом диске проверяем, что Windows видит устройство и возвращает его фактический серийный номер. До этой проверки остальные учебные диски не подключаем. Интерфейс SCSI в UTM не передаёт серийный номер, поэтому для выбранной карты дисков он не подходит

После проверки драйвера на выключенном `ad-srv` добавляем четыре отдельных динамически расширяемых образа по 4 ГиБ с интерфейсом VirtIO. Используем имена `d1`, `d2`, `d3`, `d4`. Системный диск сохраняем отдельно

После запуска сопоставляем файл образа в UTM, его Drive-запись с `Identifier`, фактический серийный номер и номер диска Windows. Серийный номер не вычисляем из `Identifier`. Сохраняем эту карту в `evidence/commands/`. После отключения и возвращения дисков сверяем её заново, поскольку номера могут измениться

```powershell
Get-Disk | Format-Table Number, SerialNumber, UniqueId, Size, IsBoot, IsSystem
```

Эту команду используем до преобразования дисков в динамические. После преобразования `Get-Disk` может не возвращать их. Для карты на всех этапах дополнительно смотрим физические устройства через `Win32_DiskDrive`. Поле `Index` сверяем с номером в Disk Management и в выводе `list disk` и `detail disk` утилиты DiskPart

```powershell
Get-CimInstance Win32_DiskDrive |
    Select-Object Index, DeviceID, Model, SerialNumber, Size
```

Диск размером 4 ГиБ считаем учебным только после сверки с картой. Во всех следующих операциях явно выбираем нужный диск по этой карте

Подключение четырёх VirtIO-дисков выполнено, реальные номера и серийные номера сверены с образами UTM. В текущей попытке карта выглядит так:

| Учебный диск | Номер Windows | SerialNumber |
|---|---|---|
| `d1` | 1 | `35D10684067C4BBC9907` |
| `d2` | 2 | `20917607355D40348669` |
| `d3` | 3 | `FF8C5B79269F4486A4B9` |
| `d4` | 4 | `DA1695117FB540359541` |

Полная связь с `Identifier` и именами qcow2 находится в [карте дисков](evidence/commands/data-disk-map.json). Эта нумерация относится к текущему стенду до отключения накопителей

Новые устройства появились как RAW, Offline и ReadOnly. После сверки всех четырёх устройств снимаем ReadOnly только с них:

```powershell
Get-Disk -Number 1,2,3,4 | Set-Disk -IsReadOnly $false
```

Команда выполнена. [Проверка доступности записи](evidence/commands/first-data-disks-writable.json) показала `IsReadOnly=False` у всех четырёх дисков. На новом стенде перед повторением команды заново сверяем номера и серийные номера

### Простой том и точка подключения

Запускаем `diskmgmt.msc`. Переводим в Online только `d1`, в текущей карте это Disk 1. В окне инициализации отмечаем только его и выбираем GPT. Остальные три учебных диска оставляем Offline

В cmd создаём пустую папку для точки подключения:

```bat
mkdir C:\Volume1
```

В Disk Management на `d1` создаём простой том 1024 МиБ. Выбираем подключение в `C:\Volume1`, файловую систему NTFS, метку `Lab5-Volume1` и Quick Format. Завершаем мастер. Диск C: и его системные разделы не изменяем

Этот этап выполнен: Disk Management показывает исправный том 1,00 ГБ. [Проверка PowerShell](evidence/commands/volume1-verification.json) подтверждает Disk 1, раздел 2 размером 1073741824 байта, путь `C:\Volume1\`, NTFS, метку `Lab5-Volume1` и состояние `Healthy`

Вывели в PowerShell четыре уровня хранения на первом сервере и сохранили результат

```powershell
Get-PhysicalDisk
Get-CimInstance Win32_LogicalDisk
Get-Partition
Get-Volume
```

`Get-CimInstance Win32_LogicalDisk` показывает логические диски, а `Get-Volume` позволяет увидеть и том без буквы, подключённый в папку. Результаты для сравнения с частью 4 сохранены в [выводе PowerShell](evidence/commands/first-storage-inventory.json)

В Disk Management переводим четыре учебных диска в Offline. Перед запуском скрипта убеждаемся, что буква `T:` свободна

### Скрипт создания T:

Скрипт проверили с отказом и подтверждением на d2. Проверка NTFS на T: вернула NoErrorsFound

Копируем [Initialize-LabVolume.ps1](scripts/Initialize-LabVolume.ps1) в `C:\Lab5`. Скрипт предназначен для части 2, пока выбранный диск остаётся базовым или RAW. После преобразования в динамический диск его не запускаем, поскольку используемые команды `Get-Disk` и `Set-Disk` не обслуживают такой диск. Запускаем его из повышенной Windows PowerShell:

```powershell
C:\Lab5\Initialize-LabVolume.ps1
```

Скрипт показывает диски и запрашивает номер. Затем проверяет размер 4 ГиБ, признаки системного и загрузочного диска, доступность записи и свободную букву `T:`. Перед удалением данных выводит идентификаторы выбранного диска и просит ввести `ERASE N`, где N - показанный номер. Любой другой ответ завершает работу без изменения диска

После подтверждения скрипт создаёт GPT, раздел на весь диск и NTFS на `T:`, запускает проверку `Repair-Volume -Scan` и выводит сведения о томе. Проверяем оба сценария: отмену и создание тома

Через Disk Management удаляем созданные учебные тома и разделы. Переводим `d1-d4` в Offline, системный диск оставляем без изменений

## Часть 3. Работа с RAID

### Создание и проверка отказа

После очистки учебных томов в части 2 переводим `d1-d3` в Online. Если диск ещё RAW, инициализируем его как GPT. Преобразуем эти три диска в динамические и создаём в Disk Management том RAID5 с буквой `W:`. `d4` оставляем свободным для восстановления

На Windows Server 2022 DiskPart показывает справку по `create volume raid`. Для массива нужны минимум три динамических диска Windows. Расширяемые образы QCOW2 экономят место на Mac, а тип диска для RAID5 задаём внутри гостевой Windows. [Документация Microsoft по созданию RAID5](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/create-volume-raid)

Сверяем серийные номера `d1`, `d2`, `d3` с картой и сохраняем их в `C:\Lab5\raid-original-serials.txt`, по одному значению на строку. В файл включаем ровно три разных непустых серийных номера исходного массива. Номера `d4` и системного диска туда не добавляем. Если серийные номера пустые или совпадают, останавливаемся и уточняем идентификацию дисков до продолжения

```powershell
notepad C:\Lab5\raid-original-serials.txt
```

После сохранения файла выполняем конвейер для обязательного артефакта задания. Он выбирает физические устройства по серийным номерам и убирает пробелы по краям значений. Проверяем, что получены ровно три строки и каждая соответствует `d1`, `d2` или `d3` в сохранённой карте

```powershell
$serials = Get-Content C:\Lab5\raid-original-serials.txt |
    ForEach-Object { $_.Trim() }

Get-CimInstance Win32_DiskDrive |
    Where-Object { ([string]$_.SerialNumber).Trim() -in $serials } |
    Select-Object Index, DeviceID, SerialNumber, Size
```

Дожидаемся завершения первоначальной синхронизации RAID-5. В Disk Management состояние тома должно стать Healthy, или «Исправен» в русской версии Windows, без продолжающейся синхронизации. Только после этого готовим файлы и проверяем отказ

Создаём два файла и сохраняем их контрольные суммы:

```powershell
'Первый файл' | Set-Content W:\one.txt
'Второй файл' | Set-Content W:\two.txt
Get-FileHash W:\one.txt, W:\two.txt
```

Перед опытом с отказом штатно выключаем `ad-srv`. Копируем файл qcow2 диска `d3` за пределы пакета `.utm`, отдельно сохраняем его исходную Drive-запись и позицию в списке дисков. Проверяем наличие копии до изменения конфигурации

Для отключения сохраняем запись `d3`, временно изменив только её интерфейс на `none`. Запись из списка `drives` не удаляем: в UTM 5.0.9 обновление списка без этой записи может удалить и сам образ из `Data`. Способ проверен на стенде. Windows показала Missing и Failed Redundancy, оба файла на W: остались доступны. После запуска сначала проверяем, что устройство `d3` исчезло из Windows, а RAID-5 перешёл в деградированное состояние. Если этого не произошло, опыт не считаем выполненным и возвращаем исходную конфигурацию

После подтверждения отключения открываем файлы на `W:` и повторно вычисляем контрольные суммы:

```powershell
Get-Content W:\one.txt, W:\two.txt
Get-FileHash W:\one.txt, W:\two.txt
```

В Disk Management сохраняем скриншот тома с отказавшим диском. Перед восстановлением сверяем `d4` по серийному номеру, переводим его в Online, при необходимости инициализируем как GPT и преобразуем в динамический диск. Проверяем, что на нём хватает нераспределённого места для всего участка, который занимал `d3`. Через Repair Volume выбираем `d4` и ждём состояния Healthy. Сохраняем второй скриншот и повторно проверяем файлы. [Требования к диску для восстановления](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/repair)

### RAID-5 на четырёх дисках

Выключаем сервер и возвращаем прежний интерфейс `d3` по сохранённой Drive-записи. Сохраняем её `Identifier`, исходный образ и позицию в списке. После запуска заново сверяем карту накопителей. Через Disk Management удаляем только учебный RAID и разделы на `d1-d4`

В DiskPart выполняем `list disk` и сверяем четыре учебных диска с картой. Звёздочка в колонке `Dyn` означает, что диск уже динамический. Удаление томов не переводит его обратно в базовый

По фактическим номерам четырёх дисков составляем файл DiskPart `C:\Lab5\Create-Raid5.txt`. Пары команд `select disk` и `convert dynamic` добавляем только для тех учебных дисков, которые ещё базовые. Уже динамические диски повторно не преобразуем. Затем добавляем одну команду `create volume raid disk=` со списком четырёх проверенных номеров. Завершаем файл командами `format fs=ntfs quick label=Lab5-RAID5` и `assign letter=V`

Файл составляем после сверки номеров. В выполненном опыте после очистки четырёх дисков добавили convert gpt и convert dynamic для каждого. [Скрипт DiskPart](scripts/Create-Raid5.txt) После чтения файла запускаем:

```powershell
Get-Content C:\Lab5\Create-Raid5.txt
diskpart /s C:\Lab5\Create-Raid5.txt
Get-Volume -DriveLetter V
```

Номинальная полезная ёмкость RAID-5 на трёх дисках по 4 ГиБ составляет около 8 ГиБ, на четырёх - около 12 ГиБ. Фактический размер будет немного меньше из-за метаданных и форматирования

## Часть 4. Подключение дисков через iSCSI

`ad-srv` предоставляет диск и выступает как iSCSI Target. `ad-srv-2` подключает его и выступает как iSCSI Initiator. Файл LUN храним на томе `V:` первого сервера

На `ad-srv` устанавливаем роль и создаём каталог:

```powershell
Install-WindowsFeature FS-iSCSITarget-Server -IncludeManagementTools
New-Item V:\iSCSI -ItemType Directory
```

Создаём LUN1 размером 5 ГиБ и разрешаем подключение второму серверу по IP:

```powershell
New-IscsiVirtualDisk -Path V:\iSCSI\LUN1.vhdx -Size 5GB
New-IscsiServerTarget -TargetName Lab5Target -InitiatorIds 'IPAddress:10.0.0.2'
Add-IscsiVirtualDiskTargetMapping -TargetName Lab5Target -Path V:\iSCSI\LUN1.vhdx
```

На ad-srv-2 запускаем службу MSiSCSI. В выполненном опыте добавили портал командой New-IscsiTargetPortal и подключили цель через Connect-IscsiTarget с IsPersistent=True. Те же действия доступны в iscsicpl.exe на вкладках Discovery и Targets

Через Disk Management на втором сервере находим новый диск с шиной iSCSI размером 5 ГиБ. После проверки его номера переводим диск в Online, создаём GPT, простой том NTFS и назначаем `R:`. К системному диску эти действия не применяем

Сохраняем сведения о томах и подключении:

```powershell
Get-PhysicalDisk
Get-CimInstance Win32_LogicalDisk
Get-Partition
Get-Volume
Get-Disk | Where-Object BusType -eq 'iSCSI'
Get-IscsiSession
```

Проверяем запись и чтение файла на втором сервере:

```powershell
'Проверка iSCSI' | Set-Content R:\iscsi-check.txt
Get-Content R:\iscsi-check.txt
```

В этом опыте `R:` является блочным диском второго сервера, а файл `LUN1.vhdx` хранится на `V:` первого сервера. Оба имени относятся к одним данным на разных уровнях хранения

## Часть 5. Работа со Storage Spaces

Выключаем `ad-srv` и добавляем семь новых отдельных динамически расширяемых образов по 10 ГиБ с проверенным интерфейсом VirtIO. Сопоставляем их фактические серийные номера с файлами образов. Диски `d1-d4`, системный диск и LUN в новый пул не включаем

После запуска проверяем новые накопители:

```powershell
Get-PhysicalDisk | Format-Table FriendlyName, SerialNumber, UniqueId, Size, CanPool
```

Через Server Manager -> File and Storage Services -> Storage Pools создаём пул `Lab5Pool`. Выбираем только семь проверенных новых дисков по 10 ГиБ. Если мастер предлагает сразу создать виртуальный диск, закрываем этот шаг, поскольку по заданию виртуальные диски создаются через PowerShell

Проверяем состав пула:

```powershell
Get-StoragePool -FriendlyName Lab5Pool | Get-PhysicalDisk
```

Создаём максимально доступный Two-way mirror и записываем фактический размер:

```powershell
New-VirtualDisk -StoragePoolFriendlyName Lab5Pool -FriendlyName Lab5Mirror `
    -ResiliencySettingName Mirror -PhysicalDiskRedundancy 1 `
    -ProvisioningType Fixed -UseMaximumSize

Get-VirtualDisk -FriendlyName Lab5Mirror |
    Select-Object FriendlyName, Size, FootprintOnPool, NumberOfColumns, PhysicalDiskRedundancy
```

Сохраняем вывод и удаляем только виртуальный диск `Lab5Mirror`, оставляя пул и его семь накопителей:

```powershell
Remove-VirtualDisk -FriendlyName Lab5Mirror
```

Подтверждаем удаление в запросе PowerShell. Проверяем завершение фоновых задач и освобождение места в пуле:

```powershell
Get-StorageJob
Get-StoragePool -FriendlyName Lab5Pool | Select-Object FriendlyName, Size, AllocatedSize
Get-VirtualDisk -FriendlyName Lab5Mirror -ErrorAction SilentlyContinue
```

После удаления `Lab5Mirror` и завершения связанных задач создаём максимально доступный Parity с защитой от отказа двух дисков:

```powershell
New-VirtualDisk -StoragePoolFriendlyName Lab5Pool -FriendlyName Lab5Parity `
    -ResiliencySettingName Parity -PhysicalDiskRedundancy 2 `
    -ProvisioningType Fixed -UseMaximumSize

Get-VirtualDisk -FriendlyName Lab5Parity |
    Select-Object FriendlyName, Size, FootprintOnPool, NumberOfColumns, PhysicalDiskRedundancy
```

Числа для сравнения берём из фактического вывода. Для зеркала две копии данных занимают примерно вдвое больше места. Для двойной чётности часть ёмкости расходуется на две независимые проверки чётности. Итог зависит также от размещения столбцов и служебных расходов, поэтому размер Parity не подставляем заранее по одной формуле

## Ответы на вопросы

Размеры и состав устройств сверяем с выводом команд после выполнения соответствующей части. Расчётные значения ниже объясняют ожидаемый результат и не заменяют измерения на стенде

### 1. В чем разница возможностей динамических и базовых дисков в Windows?

На базовом диске создаём разделы и обычные тома в пределах одного накопителя. Динамические диски Windows позволяют создавать составные, чередующиеся, зеркальные тома и RAID-5 из нескольких накопителей. В этой работе динамические диски нужны для `W:` и `V:`. Расширяемый файл qcow2 в UTM сам по себе не делает диск динамическим внутри Windows

### 2. В чем разница устройства динамических и базовых дисков в Windows?

Базовый диск хранит расположение разделов в таблице MBR или GPT. Динамический диск дополнительно использует базу LDM: в ней описаны тома и участки дисков, из которых они состоят. Копии базы находятся на динамических дисках компьютера. Поэтому один динамический том может занимать несколько накопителей. MBR/GPT и Basic/Dynamic обозначают разные свойства диска. [Описание Microsoft](https://learn.microsoft.com/en-us/windows/win32/fileio/basic-and-dynamic-disks)

### 3. Сопоставьте данные, полученные в части 2, п. 3-6. Соотнесите объекты, с которыми вы работали с элементами стека хранения Windows. Опишите результаты сопоставления и сравнения.

| Команда | Уровень хранения и связь объектов |
|---|---|
| `Get-PhysicalDisk` | Накопители, доступные провайдеру хранения. В гостевой Windows это виртуальные устройства UTM |
| `Get-CimInstance Win32_LogicalDisk` | Логические диски с буквами, например C: или T: |
| `Get-Partition` | Разделы базовых дисков, их номера, смещения и размеры |
| `Get-Volume` | Тома с файловой системой, меткой, ёмкостью и свободным местом, в том числе без буквы |

При сопоставлении сначала находим учебное устройство по карте дисков. Затем связываем его раздел и том через `DiskNumber`, `PartitionNumber` и пути доступа. Для `C:\Volume1` отдельно проверяем том, смонтированный в папку. Число физических устройств, разделов и томов может различаться: это разные уровни хранения

### 4. Каков будет размер каталога Volume1 после выполнения п. 2 части 2? Почему?

Через `C:\Volume1` будет доступен отдельный том номинальной ёмкостью 1 ГиБ на `d1`. Его свободное место будет немного меньше из-за NTFS. Это ёмкость подключённого тома, а размер содержимого пустой папки в Проводнике может быть равен нулю. Файлы, записанные через эту папку, занимают место на `d1`, ёмкость диска C: не увеличивается

После создания проверяем том по точке подключения:

```powershell
Get-Volume -FilePath C:\Volume1\ | Select-Object FileSystem, Size, SizeRemaining
```

### 5. Какой будет объем диска W: после выполнения п.1 части 3 и диска V: после п.9 части 3? Почему?

У RAID-5 полезная ёмкость равна примерно `(N - 1) × S`, где N - число дисков, S - размер используемой области на каждом. Для трёх дисков по 4 ГиБ это около 8 ГиБ на `W:`, для четырёх около 12 ГиБ на `V:`. Эквивалент ёмкости одного диска расходуется на распределённую чётность. Фактический размер тома будет немного меньше из-за служебных данных

Вывод для `W:` сохраняем до удаления первого массива, для `V:` после создания второго:

```powershell
Get-Volume -DriveLetter W | Select-Object DriveLetter, Size, SizeRemaining
```

```powershell
Get-Volume -DriveLetter V | Select-Object DriveLetter, Size, SizeRemaining
```

### 6. Дайте определения понятиям iSCSI Initiator, iSCSI Target и IQN (iSCSI qualified name).

Initiator подключается к удалённому блочному устройству и отправляет команды SCSI по IP-сети. Target принимает команды и предоставляет LUN. В нашем плане `ad-srv-2` является инициатором, `ad-srv` целью. IQN - уникальное имя узла iSCSI, состоящее из префикса `iqn`, даты, обратного доменного имени и уникального суффикса. Оно идентифицирует узел и не является IP-адресом

### 7. Как с помощью PowerShell установить iSCSI Target на локальный хост?

В повышенной Windows PowerShell устанавливаем серверную роль вместе со средствами управления:

```powershell
Install-WindowsFeature FS-iSCSITarget-Server -IncludeManagementTools
```

Создание виртуального диска, цели и разрешение подключения выполняются отдельно, как в части 4

### 8. При создании виртуального диска iSCSI возможно выбрать три типа диска Фиксированный, Динамический и Разностный. В чем разница этих типов? Придумайте реальные ситуации, когда целесообразно применять каждый из трех типов дисков.

| Тип | Как занимает место | Пример применения |
|---|---|---|
| Фиксированный | Файл сразу получает место под заданную ёмкость | Рабочая база данных, для которой заранее резервируем ёмкость |
| Динамический | Файл растёт по мере записи в пределах заданного максимума | Учебный LUN, который сначала почти пустой. Свободное место на сервере нужно контролировать |
| Разностный | Сохраняет изменения относительно родительского образа и зависит от него | Несколько учебных систем с одним неизменяемым базовым образом и отдельными изменениями |

Родительский образ разностного диска сохраняем доступным и не изменяем, иначе дочерний диск может потерять корректное содержимое. Параметр `ParentPath` для такого образа описан в [документации Microsoft](https://learn.microsoft.com/en-us/powershell/module/iscsitarget/new-iscsivirtualdisk?view=windowsserver2022-ps)

### 9. Сравните данные, полученные в части 2, п. 3-6 с данными, полученными в части 4, п. 7-10.

В части 2 устройства подключены непосредственно к виртуальной машине через VirtIO. В части 4 на `ad-srv-2` должен появиться дополнительный блочный диск с шиной iSCSI, а после разметки его раздел и том `R:`. Размер и идентификаторы сверяем с выводом обеих частей. Тип `Win32_LogicalDisk` может оставаться «локальный диск», поэтому протокол подключения проверяем по `Get-Disk` и `Get-IscsiSession`

На `ad-srv` LUN хранится как файл `V:\iSCSI\LUN1.vhdx`. На `ad-srv-2` он представлен диском, разделом и томом. Это представление одного хранилища на разных машинах и уровнях стека

### 10. Чем отличается по-вашему программный RAID и Storage Spaces? Какие аналогии из мира Linux вы можете привести?

Программный RAID в части 3 объединяет области динамических дисков в том с выбранной схемой данных и чётности. Storage Spaces сначала объединяет накопители в пул, затем выделяет из него виртуальные диски с зеркалом, чётностью или без избыточности. Пул позволяет отдельно управлять физической ёмкостью и размещёнными на ней виртуальными дисками

В Linux близкая аналогия программного RAID - `mdadm`, управления пулом и логическими томами - LVM. Для некоторых схем используют их вместе. Это аналогии по назначению, форматы метаданных и команды у них разные

### 11. Как вывести информацию о пуле Storage Spaces с помощью PowerShell?

```powershell
Get-StoragePool -FriendlyName Lab5Pool |
    Select-Object FriendlyName, HealthStatus, OperationalStatus, Size, AllocatedSize

Get-StoragePool -FriendlyName Lab5Pool | Get-PhysicalDisk
```

Первая команда показывает состояние и использование ёмкости пула, вторая его физические накопители

### 12. Как создать пул Storage Spaces с помощью PowerShell?

Используем `New-StoragePool`. Перед созданием выбираем только семь новых дисков по проверенной карте и записываем их реальные серийные номера в `C:\Lab5\pool-serials.txt`, по одному на строку. Пустые и повторяющиеся номера в файл не включаем. Пример команды для ответа на вопрос:

```powershell
$serials = Get-Content C:\Lab5\pool-serials.txt | ForEach-Object { $_.Trim() }
$disks = Get-PhysicalDisk -CanPool $true |
    Where-Object { ([string]$_.SerialNumber).Trim() -in $serials }

if ($disks.Count -ne 7) { throw 'Нужно выбрать ровно семь учебных дисков' }

New-StoragePool -FriendlyName Lab5Pool `
    -StorageSubSystemFriendlyName 'Windows Storage*' -PhysicalDisks $disks
```

В самой работе пул создаём через Server Manager, как требует часть 5. Повторно создавать уже существующий `Lab5Pool` этой командой не нужно. Параметры приведены в [New-StoragePool](https://learn.microsoft.com/en-us/powershell/module/storage/new-storagepool?view=windowsserver2022-ps)

### 13. Сравните объемы дисков из части 5 п.3 и п.5. Какой диск больше? Почему?

Две копии зеркала расходуют около половины общей ёмкости на избыточность. Двойная чётность хранит две независимые проверки для полосы данных и допускает потерю любых двух дисков. При семи столбцах она эффективнее зеркала по полезной ёмкости, поэтому ожидаем больший виртуальный диск Parity

Для семи дисков по 10 ГиБ оценки 35 ГиБ для зеркала и 50 ГиБ для двойной чётности являются теоретическими пределами без служебных расходов. Фактический максимум зависит от `NumberOfColumns`, выравнивания, метаданных и размещения свободных областей. Число столбцов определяет, по скольким накопителям распределяется одна полоса. `-UseMaximumSize` выбирает доступный размер для конкретной схемы, а не обещает эти расчётные значения

Размер `Lab5Mirror` сохраняем до его удаления, размер `Lab5Parity` после создания. В нашем опыте зеркало дало 30 ГиБ на трёх столбцах, двойная чётность - 36 ГиБ на шести. PhysicalDiskRedundancy составил 1 и 2 соответственно

## Памятка для защиты

| Термин | Значение |
|---|---|
| Базовый диск | Диск с таблицей разделов MBR или GPT |
| Динамический диск Windows | Диск с метаданными LDM, позволяющий объединять пространство нескольких накопителей в том |
| Точка подключения | Пустая папка NTFS, через которую доступен другой том |
| RAID-5 | Данные и распределённая чётность, сохраняющие доступность при отказе одного диска |
| iSCSI Initiator | Клиент, отправляющий команды SCSI по IP-сети |
| iSCSI Target | Сервер, предоставляющий блочные устройства инициаторам |
| IQN | Имя узла iSCSI, например инициатора или цели |
| Storage Pool | Набор физических дисков, из которого выделяется место виртуальным дискам Storage Spaces |
| Two-way mirror | Две копии данных, допускающие отказ одного диска |
| Dual parity | Двойная чётность с допуском отказа двух дисков |

Для отчёта сохраняем карту дисков, вывод четырёх уровней хранения до и после iSCSI, результаты проверки T:, скрипт DiskPart с реальными номерами, состояния RAID-5 до и после восстановления, команды Storage Spaces и фактические размеры обоих виртуальных дисков

Синтаксис iSCSI проверен по документации [New-IscsiServerTarget](https://learn.microsoft.com/en-us/powershell/module/iscsitarget/new-iscsiservertarget). Параметры двойной чётности и выделения максимального размера описаны в [New-VirtualDisk](https://learn.microsoft.com/en-us/powershell/module/storage/new-virtualdisk)
