# Проверка RAID5 при отключении одного и двух дисков

19 ноября 2026 года проверили том `V:` на `ad-srv`. В исходном состоянии DiskPart показал RAID-5, `Healthy` и четыре динамических диска `d1-d4`. Записали файл `V:\raid5-check.txt` со строкой `Lab 5 RAID5 independent read test` и сняли SHA-256

```text
EC9B952A12AD691B51A7D05FF92EEEE4B51E7E611699FFCB25536728E1EECD59
```

Выключили обе ВМ. Для каждого сценария запускали `ad-srv` с отдельной копией исходных образов. В UTM отключали нужные диски через `Interface=None`. Проверяли их отсутствие в Windows по серийным номерам

| Сценарий | Что показал DiskPart | Результат чтения |
|---|---|---|
| Все четыре диска подключены | `V:` `Healthy` | Файл открывается, получен исходный SHA-256 |
| Отключён `d3` | Один `Missing`, `V:` `Failed Redundancy` | Файл открывается, SHA-256 совпал |
| Отключены `d3` и `d4` | Два `Missing`, том RAID-5 `Failed`, буква отсутствует | Windows не нашла диск `V:`, файл не открылся |

При двух отключениях проверили и наличие буквы `V:`, и попытку чтения через `Get-Content`. PowerShell вернул сообщение `Cannot find drive. A drive with the name 'V' does not exist`

RAID5 выдержал один отказ. При двух отказах в каждой затронутой полосе недостаёт до двух блоков, а чётность позволяет восстановить только один. Поэтому требование открыть файл после отключения двух участников выходит за предел отказоустойчивости RAID5

## Возврат стенда

Вернули исходные файлы дисков и конфигурацию UTM. После запуска Windows снова увидела все четыре участника. Том `V:` вернулся в состояние `Healthy`, файл открылся и его SHA-256 совпал с исходным. На втором сервере iSCSI-сеанс переподключился, том `R:` показал `Healthy`, тестовый файл прочитался
